# Билдер 2.0

Редактор получил тёмное оформление с латунными акцентами, компактную навигацию и отдельные компоненты каталога и систем мортара. В широкой рабочей области таланты по-прежнему размещаются в **три колонки**, на планшете — в две, на телефоне — в одну.

## Создание персонажа

- «Основа» собрана в единое досье: имя, раса и профессия рядом с компактными изображениями; дата рождения и начальный опыт — отдельные группы. Происхождение и вера открыты ниже, а справки раскрываются рядом с соответствующим выбором. Для мортара показывается дата пробуждения и скрывается блок профессии.
- Наведение и клавиатурный фокус открывают прежнюю подробную справку; длинный тултип можно прокручивать.
- Клик или касание закрепляет описание в боковой панели с настоящими ценами и действиями движка. Панель остаётся открытой после покупки.
- Поиск и фильтры показывают все, доступные или выбранные таланты. У заклинаний есть поиск, фильтр ранга и выбранных заклинаний.
- Описание выбранного профессионального пути доступно рядом с его рангом. Все пути текущей профессии можно прочитать до выбора; смена из панели описания поддерживает предупреждение о зависимых покупках и отмену.
- Репутация вынесена в самостоятельный блок на всю ширину. Причина известности и место получения имеют полноценные поля; журнал XP находится отдельно в сворачиваемом блоке.
- Карточки систем мортара используют отдельные строки названия/ранга и условий/действий. Подробные описания по-прежнему доступны при наведении и нажатии.
- История изменений позволяет отменять и повторять решения, в том числе смену расы и загрузку персонажа. Последовательный ввод в одном поле объединяется в одно изменение. История хранится в памяти текущей вкладки; черновик сохраняется на устройстве.
- Перед сменой расы, профессии, пути или возраста с потерей зависимых покупок отображается список удаляемых решений. Отказ оставляет персонажа прежним.
- Поля характеристик и навыков сохраняют DOM-узел и фокус при вводе. У характеристик есть кнопки −/+ и объяснение предела.
- Магия появляется в маршруте для подходящего Path. На телефоне используется компактный выбор раздела.
- Подробные справки и разделы истории можно раскрывать по мере необходимости. Возрастной журнал свёрнут, чтобы каталог талантов оставался близко к началу экрана.
- Меню «Файл» содержит черновик, открытие и создание персонажа. Отказ локального сохранения отображается явно.

## Мортары и совместимость

Два наблюдателя за DOM заменены одним компонентом, вызываемым после изменения состояния. Он использует `builderRole` и результаты общего движка: Recovery, все шесть Operational Protocols, бонусы характеристик и стоимость развития. В неподвижном интерфейсе нет самоподдерживающихся DOM-изменений.

Расчёт, валидация и симуляция мортара больше не читают глобальное состояние браузерного UI и не изменяют переданный персонаж. D2/D100 выполняются после импорта в Foundry по прежнему контракту.

Формат персонажа остаётся **v8**, ZIP-пакета — **v3**. `characterId`, журналы покупок, вложенные правила и изображения сохраняются. Правила кампании и их версия не меняются из-за обновления оформления. Версия установленного импортёра остаётся 1.5.1; в репозитории пересобраны общие модули из актуального исходного ядра.

## Проверка и запуск

Откройте `offline-app/index.html` в браузере либо используйте корневой `ОТКРЫТЬ-КОНСТРУКТОР.bat`. Для GitHub Pages предназначен результат `npm run build:pages` в `dist/pages`.

```text
npm ci
npm run build:pages
npm run test:browser
```

Последняя команда запускает установленный Chrome без окна. На Windows используется стандартный путь; для другого расположения задайте `CHROME_PATH`. Снимки и временный профиль находятся в `.test-artifacts` и исключены из Git.

Автоматические проверки охватывают движок, экспорт/импорт данных, старый сценарий приложения, поиск, покупки, отмену/повтор, отказ сохранения, preview/cancel смены расы, независимость ядра от UI, отсутствие мутаций в покое и мобильную геометрию. Отдельный браузерный сценарий проверяет настоящий ZIP-экспорт, преобразование экспортированного персонажа в Actor data, повторный запуск Pages без сети, отказ/согласие на обновление правил и запуск автономного index.html через file://.

Живой импорт в запущенную Foundry и проверка интерфейса игроками остаются приёмочными проверками перед публикацией. Шрифты системные; внешние CDN и новая серверная инфраструктура не требуются.
