# Публикация конструктора через GitHub Pages

## Первичная публикация

1. Создайте репозиторий GitHub и поместите содержимое полного проектного архива в корень репозитория.
2. Основная ветка должна называться `main`.
3. В настройках репозитория откройте `Pages` и выберите источником `GitHub Actions`.
4. Сделайте commit и push. Workflow `.github/workflows/pages.yml` выполнит `npm ci`, соберёт сайт и опубликует `dist/pages`.
5. После завершения workflow адрес появится в разделе Deployments и в настройках Pages.

Workflow не привязан к конкретному имени пользователя или репозитория. Все URL внутри сайта относительные, поэтому он работает как на корневом домене Pages, так и в подпапке репозитория.

## Обновление талантов и заклинаний

1. Замените `data/source/Talents.json` и/или `data/source/Spells.json` свежими экспортами компендиумов.
2. При изменении иных правил отредактируйте `data/base-rules.json`.
3. Желательно изменить `rulesVersion` в `data/base-rules.json`, чтобы человек видел понятный номер версии. Техническое обновление всё равно определяется по SHA-256 пакета.
4. Сделайте commit и push в `main`.

Action автоматически:

- нормализует каталоги;
- сохраняет стабильные `catalogId` известных записей;
- собирает `rules/manifest.json`;
- создаёт версионированный `.flrules`;
- публикует новую версию страницы.

При следующем открытии страницы игрок получает новую версию. Проверка обновлений выполняется автоматически при запуске, без отдельной кнопки в интерфейсе.

## Что хранится у игрока

IndexedDB хранит текущий и предыдущий пакеты правил. Это позволяет:

- открыть редактор при временно недоступном GitHub;
- сохранить предыдущий пакет как технический резерв;
- не загружать повторно неизменившийся `.flrules`.

Service Worker кэширует HTML, CSS и JavaScript приложения. Манифест и `.flrules` намеренно не кэшируются Service Worker: ими управляет проверяемый механизм IndexedDB.

## Раздельный репозиторий правил

По умолчанию `config.js` указывает на `./rules/manifest.json`. Если правила должны лежать в другом репозитории или на другом домене, измените `rulesManifestUrl`. Сервер должен разрешать CORS для JSON и `.flrules`.

## Обновление логики билдера

Изменения интерфейса и движка требуют commit новой версии кода, но игрок всё равно получает её через ту же страницу. Поле `minimumBuilderVersion` в манифесте не позволяет открыть пакет правил старой несовместимой версией приложения.
