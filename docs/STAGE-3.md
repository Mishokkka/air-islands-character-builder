# Этап 3: последовательный мастер и единый `.flchar`

## Интерфейс игрока

Техническая форма преобразована в последовательный мастер из восьми этапов:

1. основа, дата рождения, происхождение, портрет и токен;
2. характеристики;
3. навыки;
4. таланты и Professional Paths;
5. заклинания;
6. языки, Base XP и Reputation;
7. биография и пожелания по снаряжению;
8. итоговая проверка и экспорт.

Игрок может переходить между этапами через боковую навигацию. Для каждого этапа показывается состояние проверки. Боковая карточка ресурсов отображает возраст, бюджеты характеристик и навыков, возрастные очки талантов, языки и остаток Base XP.

## Формат `.flchar` v3

`.flchar` теперь является ZIP-контейнером без сжатия:

```text
manifest.json
character.json
assets/portrait.webp   # необязательно
assets/token.webp      # необязательно
```

PNG и JPEG сохраняются в исходном формате. В `character.json` находятся метаданные изображений, размеры, MIME-тип и SHA-256. Импортёр проверяет размер и контрольную сумму вложения до создания Actor.

Контейнер использует собственную минимальную реализацию ZIP Store. Она не зависит от внешних библиотек и работает локально через `file://`.

## Изображения

Автономный конструктор принимает PNG, WebP и JPEG до 12 МБ. Изображения включаются и в готовый файл, и в файл черновика.

Для автоматического восстановления текущего локального черновика браузер пытается хранить изображения в IndexedDB. Если браузер ограничивает IndexedDB для локальных файлов, текстовый черновик сохраняется как раньше, а интерфейс предупреждает, что изображение нужно выбрать повторно.

При импорте Foundry:

1. проверяет контейнер и изображения;
2. создаёт уникальную папку в `Data/worlds/<world>/air-islands-character-assets/`;
3. загружает портрет и токен через FilePicker;
4. назначает портрет `Actor.img`;
5. назначает токен `prototypeToken.texture.src`;
6. при отсутствии отдельного токена использует портрет и для токена.

Импорт старых JSON-файлов `.flchar` v2 сохранён. После открытия в конструкторе они мигрируются в v3.
