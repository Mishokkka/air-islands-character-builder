# Конструктор персонажей Воздушных Островов

Версия 1.3.0 браузерного конструктора персонажей Forbidden Lands и модуля импорта для Foundry VTT.

Основная проверенная конфигурация: Foundry VTT 13.351 и Forbidden Lands 13.0.5. Кодовая база подготовлена для Foundry VTT 14, но отметка `verified` сохранена на 13.351 до испытания с V14-совместимой версией системы Forbidden Lands.

## Состав проекта

Проект состоит из трёх связанных частей:

1. Веб-редактор для GitHub Pages, который автоматически получает актуальные правила и обновления кода.
2. Локальная резервная версия, способная работать без интернета со встроенным пакетом правил.
3. Модуль Foundry, который управляет правилами кампании, экспортирует `.flrules` и импортирует готовые `.flchar`.

Рекомендуемый путь для игрока: открыть постоянную страницу GitHub Pages, создать персонажа и передать ГМу один файл `.flchar`. Правила загружаются автоматически, проверяются по SHA-256 и сохраняются в IndexedDB. Если GitHub временно недоступен, используется последняя успешно загруженная версия.


## GitHub Pages и автоматические обновления

Команда `npm run build:pages` создаёт готовый статический сайт в `dist/pages`. Сайт не содержит `rules.bundle.js`: при запуске он читает `rules/manifest.json`, загружает указанный `.flrules`, проверяет размер, SHA-256, минимальную версию билдера и внутренний `packageHash`.

Проверка и обновление правил выполняются автоматически и не занимают место в интерфейсе игрока. В шапке оставлены только сохранение черновика, открытие `.flchar`, сброс и экспорт персонажа. Service Worker сохраняет оболочку приложения, поэтому после первого открытия редактор продолжает запускаться без сети, используя правила из IndexedDB.

В репозитории уже находится workflow `.github/workflows/pages.yml`. При каждом push в ветку `main` он устанавливает зависимости, пересобирает каталоги, создаёт версионированный `.flrules` и публикует сайт через GitHub Pages. Для обновления данных достаточно заменить `data/source/Talents.json` и/или `data/source/Spells.json`, при необходимости изменить `data/base-rules.json`, затем сделать commit и push. Игрокам ничего перескачивать не требуется.

Подробная инструкция находится в `docs/GITHUB-PAGES.md`.

## Автономный редактор

Запуск:

```text
offline-app/index.html
```

В Windows также можно использовать:

```text
ОТКРЫТЬ-КОНСТРУКТОР.bat
```

Создание разделено на восемь этапов:

1. Основа, происхождение, вера, дата рождения и изображения.
2. Характеристики.
3. Навыки.
4. Таланты.
5. Заклинания.
6. Языки и Reputation.
7. Биография.
8. Проверка и экспорт.

Редактор проверяет возраст, расовые и профессиональные фокусы, бюджеты характеристик и навыков, единственный Professional Path, возрастные очки талантов, последовательный журнал Base XP, доступность школ, лимит пяти заклинаний каждого ранга, языковые очки, источники Reputation, слухи и обязательные поля кампании.

Текущий Base XP указывается на первом этапе. На развитие доступно 20% от этого значения с округлением вверх. Языковые очки рассчитываются только из стартовых WITS и Lore: последующая покупка Lore за Base XP их не увеличивает.

### Каталоги

General Talents показаны в отдельной трёхколоночной таблице. Заклинания сгруппированы по рангам и доступным школам. Наведение или клавиатурный фокус открывает полное описание таланта или заклинания.

При создании разрешён только один Professional Path. Его можно повышать возрастными очками и Base XP, но нельзя приобрести другой Path той же или иной профессии.

Для магического Path обязательное заклинание следующего ранга можно купить прямо на вкладке талантов. Изменение характеристик, стартовых навыков и других ранних выборов сохраняет совместимые таланты, заклинания и XP-покупки.

Покупки за Base XP можно отменять непосредственно там, где они были сделаны: в строках навыков, расового таланта, Professional Path, выбранных General Talents и в каталоге заклинаний. У каждой записи журнала Base XP также есть отдельная кнопка отмены. При удалении покупки редактор сохраняет совместимые последующие операции и убирает только те, которые потеряли предварительные условия.

### Контекстные справки

На этапе основы редактор показывает краткие карточки выбранной расы, профессии, происхождения и веры. При выборе языка показывается его описание и особые правила стоимости. Справки являются кратким открытым лором и не заменяют полные книги мира.

### Проверка ошибок

Ошибки и предупреждения показываются по этапам. Каждая запись кликабельна: редактор открывает нужный раздел, прокручивает страницу к проблемному полю и временно выделяет его.

### Итоговая сводка

Перед экспортом формируется читаемый лист со следующими данными:

- портрет, имя, раса, профессия, Path, происхождение, гражданство и вера;
- характеристики, навыки, таланты, заклинания и языки;
- источники Reputation и остаток Base XP;
- концепт, внешность, семья, предыстория, Pride и Dark Secret;
- мотивация, связь с группой и ответы на семь вопросов;
- слухи, запросы ГМу и пожелания по снаряжению.

Сводка служит только для итоговой проверки перед экспортом `.flchar`. Отдельные экспорты PDF, HTML и TXT отсутствуют.



### Интеграция Quick Access 1.7.0

- Репутация создаётся структурированными строками: количество, причина и место получения.
- Импортёр переносит строки в журнал Reputation модуля Quick Access.
- Импортёр автоматически выбирает расовый и первый профессиональный талант для расчёта стартового Willpower в Quick Access.
- Вся анкета переносится в новый структурированный профиль BIO Quick Access: Pride, Dark Secret, предыстория, семья, мотивация, связь с группой, публичная заметка, вопросы, языки и слухи.
- Языки импортируются отдельными строками с уровнем, родным статусом и фактической стоимостью изучения.
- Слухи импортируются отдельными строками с именем персонажа, текстом и скрытым статусом правды.
- Карта пилигрима получает имя, расу, подрасу, страну выдачи, дату рождения, портрет и все поля внешности.
- Старые `.flchar` с массивом `reputation.origins` и слухами без имени автоматически нормализуются в формат v8.

### Обновление каталогов 1.1.0

## Пакет правил `.flrules`

Модуль Foundry экспортирует актуальный пакет правил прямо из мира. В него входят:

- дата и название кампании;
- доступные расы, профессии и Paths;
- краткие лорные карточки;
- правила возрастов, фокусов, навыков, языков и опыта;
- актуальные снимки талантов и заклинаний из компендиумов мира;
- ограничения биографии, слухов, изображений и Base XP;
- контрольный хеш пакета.

На GitHub Pages пакет загружается автоматически по манифесту и применяется без служебных кнопок в интерфейсе игрока. После смены пакета текущий персонаж немедленно перепроверяется.

## Файл персонажа `.flchar` v8

`.flchar` является ZIP-контейнером без сжатия:

```text
manifest.json
character.json
rules.json
assets/portrait.<png|webp|jpg>
assets/token.<png|webp|jpg>
```

`character.json` содержит стабильный `characterId`, анкету и воспроизводимые журналы покупок. `rules.json` содержит проверенный пакет правил, по которому персонаж был создан. Благодаря этому новые таланты и заклинания можно импортировать без обязательного обновления встроенного каталога импортёра. Изображения необязательны. Допустимые типы и максимальный размер задаются пакетом кампании. По умолчанию разрешены PNG, WebP и JPEG до 12 МБ.

Редактор открывает старые форматы v2–v7 и переводит их в актуальный формат v8. Для старых файлов доступный при создании Base XP сохраняется при миграции. Персонажи, в которых ранее был приобретён дополнительный Professional Path, не пройдут актуальную проверку до удаления этой операции.

## Foundry-модуль

Установка:

```text
Data/modules/air-islands-character-importer/module.json
```

После активации откройте `Настройки игры` → `Настройки модулей` → `Air Islands Character Importer` → `Открыть инструменты`. В панели доступны три действия:

- `Импорт персонажа`;
- `Настройки конструктора`;
- `Экспорт .flrules`.

Каталог Actors больше не изменяется модулем ни в Foundry VTT 13, ни в Foundry VTT 14.

### Настройки кампании

Окно настроек позволяет ГМу задать:

- название, вступительный текст и текущую дату кампании;
- доступные расы, профессии и Professional Paths;
- скрытые General Talents и школы магии;
- максимальный Base XP;
- способ расчёта количества слухов;
- обязательные поля биографии;
- разрешённые типы и максимальный размер изображений.

Настройки хранятся на уровне мира и попадают в следующий экспорт `.flrules`.

### Предварительная проверка импорта

До создания Actor модуль показывает:

- совпадение хеша правил;
- ошибки и предупреждения общего движка;
- найденные актуальные Items;
- Items с изменившимся описанием;
- Items, для которых придётся использовать снимок из пакета;
- путь загрузки портрета и токена;
- Actor с тем же именем;
- ранее импортированный Actor с тем же `characterId`.

ГМ явно выбирает одно из действий:

- создать нового Actor;
- обновить Actor, ранее импортированный из того же `characterId`, сохранив вручную добавленные предметы;
- выбрать любого существующего Actor типа `character`, полностью очистить его и заменить данными из `.flchar`.

При полной замене удаляются все Items и Active Effects, старые системные данные, flags, изображение и настройки прототипа токена. Папка Actor и права доступа сохраняются. Перед операцией выводится отдельное предупреждение.

Окно предварительной проверки ограничивается высотой экрана. Всё содержимое, включая выбор действия и выбор существующего Actor, находится в одной прокручиваемой области. Стандартные кнопки DialogV2 остаются закреплены в пределах окна.

Полная анкета импортируется в поле Bio. Поле Note заполняется отдельным публичным описанием того, что наверняка знают о персонаже товарищи и знакомые.

## Сборка и тесты

Требуется Node.js 22 либо совместимая версия.

```bash
npm ci
npm run build
npm run build:pages
```

Проверяются:

- движок правил и последовательные журналы покупок;
- контейнеры `.flchar`;
- браузерный интерфейс;
- лорные карточки и итоговая сводка;
- кликабельные ошибки;
- настройки, экспорт `.flrules` и строгий импорт;
- совместимость общей кодовой базы Foundry VTT 13/14.

## Ограничения 1.3.0

- Нативное приложение Tauri не входит в эту версию. Редактор запускается в браузере.
- Модуль не отслеживает дни рождения и не изменяет уже созданных персонажей автоматически.
- Снаряжение и деньги по-прежнему выдаются ГМом вручную.
- Базовая дата кампании: `1 Хладохода 882 П.П.`. При необходимости ГМ может изменить её в настройках мира перед экспортом `.flrules`.
- Реальный запуск на Foundry VTT 14 должен быть проверен после появления совместимой версии Forbidden Lands.
